# 2026-06-15 - No-stop-after-build rule clarified

## Intent

Убрать двусмысленность в проектных правилах, из-за которой агент мог воспринимать `npm run build` как допустимую промежуточную точку остановки даже для задач по живому сайту.

## Context

Жесткое активное решение `site-task = commit -> push -> deploy -> live-check` уже было зафиксировано в `DECISIONS.md`, `CURRENT_STATE.md` и `AGENTS.md`. Но в быстрых инструкциях для мелких правок слишком заметно выделялись локальные шаги `build` и `required check`, из-за чего они визуально выглядели как самодостаточный финишный минимум.

## Changes

- В `AGENTS.md` добавлен прямой запрет останавливаться на статусе `локально изменено` без явной просьбы владельца.
- В `AGENTS.md` отдельно зафиксировано, что параллельная работа другого чата сама по себе не является основанием не делать `commit -> push -> production/live-check`.
- В `docs/quick-edit-playbook.md` добавлено явное пояснение, что `npm run build` - это только local preflight, а не финиш.
- В `docs/tilda-zero-editing.md` добавлено то же уточнение для обычных visual/content правок.
- В `docs/price-section-editing.md` `build` переописан как preflight, а остановка после него названа незавершенной site-task.

## Verification

- `git diff --check`

## Result

Теперь верхнеприоритетные docs говорят одно и то же: для живого сайта нельзя останавливаться после локального `build`, если владелец прямо не попросил отложить публикацию.
